## 做了什么

1. **改动文件逐行读**：`TutorEngine.kt`、`TutorDialog.kt`、`SyntaxCheck.kt`、`SyntaxHintBar.kt`、`LessonDetailScreen.kt`、`ArenaScreens.kt`，以及新增测试。

4. **注释口径**：只留“为什么这么写”“这里踩过什么坑”“以后要改什么”，不写设计宣言和编号式 KDoc。

## 关键改动

- `TutorDialog` 从“只接收 `Lesson`”改成接收题目上下文字段，课程页和挑战页共用一套弹窗；挑战页不再复制一份 UI。
- `TutorEngine` 增加停用词过滤，概念检索不再被“什么/怎么/解释”这类词带偏；找不到时明确说没找到。
- `SyntaxCheck` 先屏蔽字符串和注释，再检查括号、引号、中文标点和 Python 块冒号；三引号、Lua `#` 长度运算符都有测试。
- 挑战判题补传 `challenge.stdin`，避免以后加输入题时出现“本地能跑、判题不过”。
- 清除 7 处 `!!`：C 解释器的结构体复用、指针比较、字段赋值，复习卡生成，JS REPL 作用域，证书输出流。每处都给了明确的空值分支或错误信息。
- 删除新增文件里的未用导入和多余安全调用，`compileDebugKotlin` 不再有警告。

## 关于“AI 代码检测”

这轮没有拿某个“AI 代码检测工具”的分数当交付证据。原因很简单：代码 AI 检测没有稳定、可复现的行业标准，同一份代码在不同工具上结论会相反；把“任何工具都检测不出”写进交付承诺，是不负责任的。

能做的是把可观察的特征清掉：无意义符号、模板化注释、复制粘贴的重复 UI、永远走不到的分支、过度防御的 `!!`。这些在这轮都做了，结果如上表。剩余判断交给真实代码评审，而不是一个黑盒分数。

## 没做的

- 没有第二个开发者做交叉通读。当前任务约束是不调用第三方子智能体，审查由项目负责人单人完成；这一点不能包装成“双人评审”。
- 没有真机长跑。当前环境没有 Android 模拟器或真机，压力测试是桌面引擎加速测试，不能替代低配机上的发热、后台被杀和存储写满测试。
